Generated by 'make generate-extensions' from the extension registries. Do not edit: change the registration in Go and regenerate.

An extension registers itself from an `init` function that a distribution build reaches through a blank import. The host derives the namespace from the registering module, so a name is `namespace/name` and two authors cannot land on one name by choosing it. Configuration may write the bare name while only one namespace answers to it, and must write the qualified name once two do.

Every entry carries the same descriptor. `version` is the implementation's own; `contract` is the version of the extension contract it was compiled against, and a host serving another major refuses it at registration rather than at first use. `stability` says what may change between releases: an experimental entry may change in any release, a stable one needs a major release and a migration note, and a deprecated one names what replaces it.

A registration missing any mandatory field does not compile into a working binary, so nothing on this page is a placeholder.

A section a kind has no registration for is absent rather than empty. Route sets are absent and stay absent: the in-process contract that registered them is deleted, and a module is declared in configuration rather than compiled in, so the host serves its routes and its state store at `/api/v1/modules/<namespace>/` without it registering here.

The machine-readable copy of this page is `docs/extensions/extensions.json`.

## Printer connectors

Written against `sdk/connectorapi`.

### `core/echo` {#core-echo}

Reference inbound dialect: JSON over HTTP, a long poll for commands, a post for each result.

- **config name** `echo`
- **qualified name** `core/echo`
- **module** `github.com/prusa3d/prusa-connect`
- **version** 1.0.0
- **contract** 1.0.0
- **stability** experimental

The plainest dialect that is still real. A device opens the connection, says what it is, and is driven over the five routes it dialled. It authenticates nothing: the token it mints proves only that a device completed a handshake, and a dialect carrying credentials checks them before it calls Admit. Copy it and replace the five handlers with a vendor's own framing.

#### Configuration

- **`queue_depth`** int, optional, default `16`. How many commands may wait for one device before the host is told it is not keeping up.
- **`poll_window`** duration, optional, default `25s`. How long a command poll waits before answering that nothing arrived.

### `core/xbuddy` {#core-xbuddy}

The dialect Prusa xBuddy and Buddy boards speak, over the frozen registration and websocket wire.

- **config name** `xbuddy`
- **qualified name** `core/xbuddy`
- **module** `github.com/prusa3d/prusa-connect`
- **version** 1.0.0
- **contract** 1.0.0
- **stability** stable

The only dialect with machines in the field, so its wire is frozen rather than chosen: the registration handshake, the nine-byte framing and the verb rewrite are what firmware that cannot be updated on our schedule already speaks. It is inbound, so nothing in configuration names a printer: the printer registers, waits to be approved, and then dials.

#### Configuration

- **`mode`** string, optional, default `none`. The credential a printer presents on the websocket: none, token, fingerprint or both.
- **`auto_register`** bool, optional, default none. Retired, and it has no default because the mode decides. Whether a registration is approved the moment it is made is the admission mode and nothing else, so this key is accepted only where it says what the mode already says: true in mode none, which admits every printer that dials, and false in mode token, fingerprint and both, where the registration is the credential and an operator decides. Any other combination is refused at startup, with a sentence naming the mode that does what was asked for.
- **`max_registrations`** int, optional, default `400`. How many printers this driver keeps a registration for. The registration path carries no credential, so this is what bounds a table anything that can open a socket may write to. Over it, the oldest registration no printer completed is dropped.
- **`queue_depth`** int, optional, default `32`. How many commands may wait for one printer, whether it is connected or away.
- **`chunk_write_ceiling`** int, optional, default `1011`. How many bytes of the file one transfer chunk may carry, whatever chunk size the printer asks for. The default puts exactly 1024 bytes on the TLS connection per write - payload, the nine-byte transfer header and the four-byte WebSocket header - because Buddy firmware compiles mbedTLS with a 1024-byte record buffer and drops the connection on anything longer. It never advertises that limit, so raise this only for a board known to read larger records, and only where nothing between host and printer re-frames the stream.
- **`offline_grace`** duration, optional, default `0s`. Close a session whose printer has been away that long. Zero lets a session outlive any absence.
- **`default_storage`** string, optional, default `/usb`. The firmware-side mountpoint a path with no storage segment resolves against.
- **`read_deadline`** duration, optional, default `1m0s`. How long a printer's connection may say nothing before it is reported unreachable. It is what notices a link that drops packets rather than hanging up, and shortening it is the only way to notice one sooner.
- **`ping_interval`** duration, optional, default `54s`. How often the host asks a printer to prove it is there. Every frame the printer sends re-arms the read deadline, and a pong is what a quiet printer sends, so this sits below it and never above the shipping 54s.
- **`ping_timeout`** duration, optional, default `10s`. How long writing one ping may take before the connection is treated as stuck.
- **`listener`** object, optional, default `no socket`. A socket of this dialect's own for printers to dial, with addr, tls and handshake_timeout under it. No block is the default, and printers then dial the server's own listener. The certificate must be ECDSA, because the firmware offers one cipher suite and that suite needs an ECDSA key.
- **`command_deadline`** duration, optional, default `1m0s`. How long one command waits for the printer to answer it, counted from the moment its frame is written. A printer that reports telemetry and answers nothing keeps its connection healthy, so this is the only thing that ends that wait. A G-code command is answered when the printer accepts it, and the printer refuses every other command until it finishes, so this also bounds how long the next command is held while a G-code command runs.

### `core/filesystem` {#core-filesystem}

A storage root on the local disk, the built-in every deployment has.

- **config name** `filesystem`
- **qualified name** `core/filesystem`
- **module** `github.com/prusa3d/prusa-connect`
- **version** 1.0.0
- **contract** 1.0.0
- **stability** stable

It is what makes the resource plane observable without an operator installing anything first. The root is created when it does not exist, with permissions that make it the operator's and nobody else's. #### Configuration

### `core/local` {#core-local}

Keeps objects in a directory on the server's own disk, addressed as local.

- **config name** `local`
- **qualified name** `core/local`
- **module** `github.com/prusa3d/prusa-connect`
- **version** 1.0.0
- **contract** 1.0.0
- **stability** stable

Every caller-supplied name is resolved through a directory handle on the store, so a symlink or a Windows junction planted inside it is refused rather than followed. A hardlink and a bind mount are not steps in path resolution and are outside what any confinement can see. Uploads are written to a sibling temporary file and renamed on success, so a transfer that fails partway leaves the existing object alone. The SHA-256 of each object is kept in a reserved directory at the store root, so a later Stat reports the digest the write computed. The label defaults to Local disk.

#### Configuration

- **`path`** string, optional, default none. The directory this instance owns. It is created when it does not exist.

- **`allowed_extensions`** list, optional, default none. What an upload into this storage may be called. Omit the key for the built-in list of print-file and image extensions; write an empty list to permit any extension.

## Identity providers

Written against `sdk/authapi`.

### `core/oidc` {#core-oidc}

Authenticates people against an OpenID Connect issuer with the authorization code flow.

- **config name** `oidc`
- **qualified name** `core/oidc`
- **module** `github.com/prusa3d/prusa-connect`
- **version** 1.0.0
- **contract** 1.1.0
- **stability** stable

OAuth 2.1: authorization code with PKCE, S256 only, and an ID token whose signature is checked before any claim in it is read: with an algorithm the issuer advertises, against its published keys, or against the client secret for HS256. The provider holds no state between the redirect and the callback, so a restart or a second instance still completes a login. It re-checks nothing after login: an ID token is a statement about one moment, and re-checking a subject needs a token this provider is not given.

#### Configuration

- **`issuer`** url, required, default none. The issuer, whose metadata is read from its .well-known/openid-configuration.
- **`client_id`** string, required, default none. The client id this server is registered under at the issuer.
- **`client_secret`** secret, optional, default none. The client secret, for a confidential client. A public client with PKCE needs none.
- **`scopes`** list, optional, default `openid profile email`. The scopes asked for at the authorize endpoint.
- **`role_claim`** string, optional, default `roles`. The ID token claim the granted roles are read from.
- **`timeout`** duration, optional, default `10s`. How long one call to the issuer waits.

### `core/prusa-account` {#core-prusa-account}

Verifies a Prusa Account token a caller presents on every request.

- **config name** `prusa-account`
- **qualified name** `core/prusa-account`
- **module** `github.com/prusa3d/prusa-connect`
- **version** 1.0.0
- **contract** 1.1.0
- **stability** experimental

The token is an RS256 JSON Web Token from Prusa Account, sent as Authorization: Bearer or in the auth.access_token cookie. Its signature is checked offline against the issuer's published key set, cached for two hours or for as long as the issuer's cache headers say, and refetched once when a token names a key not held. The issuer, the audience, the expiry and the not-before are checked; alg none and every algorithm but RS256 are refused. The subject it yields reaches this server only through a pairing an administrator wrote at POST /api/v1/auth/pairings. There is no login flow: a person signs in at Prusa Account.

#### Configuration

- **`issuer`** url, required, default none. The issuer the token's iss claim must name.
- **`jwks_url`** url, required, default none. Where the issuer publishes its signing keys as a JSON Web Key Set.
- **`audience`** string, optional, default none. The audience the token's aud claim must contain. Empty skips the check.
- **`clock_skew`** duration, optional, default `2m`. How far a token's expiry and not-before may be out before it is refused.
- **`timeout`** duration, optional, default `10s`. How long one fetch of the key set waits.

## Event sinks

Written against `sdk/eventsapi`.

### `core/amqp` {#core-amqp}

Publishes each domain event to an AMQP 0-9-1 exchange, keyed by the event type.

- **config name** `amqp`
- **qualified name** `core/amqp`
- **module** `github.com/prusa3d/prusa-connect`
- **version** 1.1.0
- **contract** 1.1.0
- **stability** stable

One JSON message per event on a topic exchange, with the event type as the routing key, so a consumer binds to printer.# and gets printer events and nothing else. Publisher confirms are on, so a message the broker refused is counted and reported at Close rather than written to a socket and forgotten. It does not wait for the broker: a sink that refused to start because a broker is down would turn an optional integration into a boot dependency.

#### Configuration

- **`url`** url, required, default none. The broker, as amqp://user:pass@host:port/vhost or amqps:// for TLS.
- **`exchange`** string, optional, default `prusa.events`. The exchange events are published to. An empty value publishes to the default exchange.
- **`exchange_type`** string, optional, default `topic`. The exchange type declared at connect: topic, direct, fanout or headers.
- **`declare_exchange`** bool, optional, default `true`. Declare the exchange on connect. Turn it off where the topology is owned elsewhere.
- **`routing_key_prefix`** string, optional, default none. Prepended to every routing key, for a broker shared with other publishers.
- **`persistent`** bool, optional, default `true`. Mark messages persistent, so a broker restart does not lose what is queued.
- **`queue_depth`** int, optional, default `256`. How many events may wait for a slow broker before the oldest are dropped.
- **`heartbeat`** duration, optional, default `30s`. The AMQP heartbeat interval proposed to the broker.
- **`connect_timeout`** duration, optional, default `10s`. How long one connection attempt and its handshake wait.
- **`tls_skip_verify`** bool, optional, default `false`. Accept any broker certificate. For a lab broker, never for a deployment.

#### Published on its own transport

- **`printer.state_changed`** version 1.1.0. A printer's connection or print state changed. Data is the printer id and the state.
- **`printer.labels_changed`** version 1.1.0. A printer's label set changed. Data is the printer id, the mode and the labels.
- **`printer.deleted`** version 1.1.0. A printer was removed. Data is the printer id.
- **`job.updated`** version 1.1.0. A job was created or changed. Data is the job, its printer and its state.
- **`label.deleted`** version 1.1.0. A label was removed. Data is the label id.
- **`fact.observed`** version 1.1.0. A durable event from the host's bus. Data is the envelope: origin, type, class, time, sequence, epoch, causation id and the payload the emitter owns.

- **`produce_timeout`** duration, optional, default `5s`. How long the leader waits for the replicas it was told to wait for.

- **stability** stable

The still images are the frames the device sends to PUT /api/v1/cameras/{camera}/snapshot, or, when snapshot_url is set, the image this server fetches from it. The stream is optional: an rtsp:// address is read as H.264 and served to a browser through the WebRTC relay, and an http:// address is relayed as MJPEG. It is read only while somebody watches. A user name and password go in the address, and are kept out of every log.

#### Configuration

- **`snapshot_url`** url, optional, default none. An address this server fetches a still image from. Empty takes the images the camera sends.
- **`stream_url`** url, optional, default none. An rtsp:// address of an H.264 stream, or an http:// address of an MJPEG stream. Empty is no stream.
- **`stale`** duration, optional, default `5m`. How long a sent image is shown after it arrived. Past it this camera answers as one that has produced nothing.

### `core/mjpeg` {#core-mjpeg}

Reads a camera that answers a JPEG on one URL and a multipart MJPEG stream on another.

- **config name** `mjpeg`
- **qualified name** `core/mjpeg`
- **module** `github.com/prusa3d/prusa-connect`
- **version** 1.0.0
- **contract** 1.0.0
- **stability** stable

The simplest camera there is, and the one most devices already are: an HTTP snapshot endpoint and an HTTP multipart stream endpoint. Nothing is decoded or re-encoded, so the cost is the transfer and nothing else. Frames from the device are bounded and are refused unless they are JPEG, because a camera is an untrusted device on somebody's network and its answer is served to a browser.

#### Configuration

- **`snapshot_url`** url, optional, default none. The endpoint that answers one JPEG. Without it this camera declares no still image.
- **`stream_url`** url, optional, default none. The endpoint that answers a multipart MJPEG stream. Without it this camera declares no stream.
- **`username`** string, optional, default none. The basic-auth user the camera requires. It is never logged, reported or echoed back.
- **`password`** secret, optional, default none. The basic-auth password. It is never logged, reported or echoed back.
- **`timeout`** duration, optional, default `5s`. How long one snapshot fetch waits before it is abandoned.
- **`min_interval`** duration, optional, default `10s`. The shortest gap between two fetches from the device. Requests inside it are served the frame already held.
- **`max_frame_bytes`** int, optional, default `8388608`. The ceiling on one frame. A device answering with an endless body is cut off here.
- **`insecure_skip_verify`** bool, optional, default `false`. Accept an https camera whose certificate does not verify. It is a camera on a LAN, so this is sometimes the only option, and it is off unless the operator says so.

### `core/push` {#core-push}

Holds the frames a camera pushes to this server, for a camera nothing here can dial.

- **config name** `push`
- **qualified name** `core/push`
- **module** `github.com/prusa3d/prusa-connect`
- **version** 1.0.0
- **contract** 1.0.0
- **stability** stable

A camera behind a router or on a network this server has no route to cannot be read, so it sends its own frame to PUT /api/v1/cameras/{camera}/snapshot and this driver holds the last one. The snapshot and the stream paths then serve it exactly as they serve a frame the host fetched. Nothing is decoded or re-encoded. A camera that stops sending is reported as one that has produced no frame, rather than showing its last picture forever.

#### Configuration

- **`stale`** duration, optional, default `5m`. How long a pushed frame is served after it arrived. Past it this camera answers as one that has produced nothing.

### `core/rtsp` {#core-rtsp}

Reads an H.264 camera over RTSP, which is what the Prusa Buddy3D camera speaks.

- **config name** `rtsp`
- **qualified name** `core/rtsp`
- **module** `github.com/prusa3d/prusa-connect`
- **version** 1.0.0
- **contract** 1.0.0
- **stability** experimental

Opens one RTSP session per viewer, interleaved over the one TCP connection, and hands the host the H.264 elementary stream. The host repacketises that into WebRTC, so a browser plays a camera whose own answer is otherwise VLC. Nothing is decoded or re-encoded. A camera that describes H.265 is refused with a reason, because no browser matrix covers it and nothing here can convert it. The session is opened when a viewer arrives and closed when they leave, so an idle camera holds no device socket.

#### Configuration

- **`url`** url, required, default none. The RTSP stream, such as rtsp://192.168.1.50/live. rtsps carries the same session over TLS.
- **`snapshot_url`** url, optional, default none. An HTTP endpoint answering one JPEG, for the thumbnail grid. Without it this camera declares no still image.
- **`username`** string, optional, default none. The user the camera challenges for. It is never logged, reported or echoed back.
- **`password`** secret, optional, default none. The password the camera challenges for. Digest is answered where the camera offers it. It is never logged, reported or echoed back.
- **`timeout`** duration, optional, default `5s`. How long one handshake message waits before the session is abandoned.
- **`max_unit_bytes`** int, optional, default `4194304`. The ceiling on one H.264 NAL unit. A device that fragments without ever ending a unit is cut off here.
- **`verify_certificate`** bool, optional, default `false`. Require an rtsps camera's certificate to verify. A camera on a LAN rarely has one that does, so it is off unless the operator says so.
