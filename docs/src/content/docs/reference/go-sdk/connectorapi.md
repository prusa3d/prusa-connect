A printer driver is a dialect: the code that speaks one make of machine.
`connectorapi` is the contract a driver implements and the host drives it
through. A driver declares what its code can do with `Baseline`, and takes
every command through one entry point, `Do`, on a `Session`.

The host owns both directions. `Outbound` is the host dialling an address
configuration names; `Inbound` is a device dialling routes the host mounted
for the driver. A driver implements at least one, and everything after the
session is the same. The host resolves a capability set, validates every
argument against it before `Do` is reached, and supervises the session. Two
rules bind everything. Capability sets merge by intersection only, so a
profile or a probe can remove a key the baseline declared and can never add
one. And a name is a contract: a key whose meaning changes gets a new name.

A driver registers from `init` with `Register` and a factory. The factory is
handed no host service, so a driver cannot reach a device before the host is
ready. [`connectorapitest`](./connectorapi-connectorapitest.md) is the suite
every driver passes.

```go
package acmeshelf

import (
	"context"

	"github.com/prusa3d/prusa-connect/sdk/connectorapi"
	"github.com/prusa3d/prusa-connect/sdk/extension"
)

const setTemperature connectorapi.Capability = "core.command.set_nozzle_temperature"

// driver is the dialect. It holds nothing per device.
type driver struct{}

// Baseline is everything this code can do, for any shelf. A profile the host
// resolves may remove a key from it and can never add one.
func (driver) Baseline() connectorapi.Set {
	return connectorapi.Set{
		connectorapi.VerbSendInfo: {Flag: true},
		setTemperature:            {Flag: true},
		connectorapi.ArgumentKey(setTemperature, "target"): {
			Flag: true, Kind: connectorapi.KindInteger, Required: true,
			Limit: 300, HasLimit: true, Min: 0, HasMin: true,
		},
	}
}

// Connect dials one shelf and returns its session. The set the session
// reports is the baseline narrowed by the profile, never widened.
func (d driver) Connect(
	ctx context.Context, endpoint connectorapi.Endpoint, profile connectorapi.Set,
) (connectorapi.Session, error) {
	wire, err := dial(ctx, endpoint.Address)
	if err != nil {
		return nil, err
	}

	return &session{
		wire:    wire,
		caps:    d.Baseline().Intersect(profile),
		patches: make(chan connectorapi.StatePatch),
	}, nil
}

func init() {
	connectorapi.Register("acme-shelf", extension.Doc{
		Summary:     "Drives an Acme filament shelf over its serial line",
		Description: "Dials the address configuration names, reports the shelf's state tree and sets a slot's temperature.",
		Version:     "0.1.0",
		Contract:    connectorapi.Contract,
		Stability:   extension.StabilityExperimental,
	}, func(connectorapi.Spec) (connectorapi.Driver, error) {
		return driver{}, nil
	})
}
```

`session` implements `Session` and is the dialect's own wire code, which is
not shown. A refusal the machine decided is a `Result` with `OK` false and a
nil error, and `MachineReason` carries the machine's own word. An error from
`Do` means something broke on the way, and the host counts it as a failure.

## `connectorapi` {#connectorapi}

```go
import "github.com/prusa3d/prusa-connect/sdk/connectorapi"
```

Package connectorapi is the contract a printer driver implements and a host drives it through. A driver declares what its code can do with Baseline, and takes commands through the single Do entry point on a Session.

A driver implements Outbound when the host dials the device, Inbound when the device dials the host, or both. Sessions behave the same either way.

A profile or a probe may remove a capability that Baseline declared. It may never add one.

A capability key or an argument name never changes its meaning. A changed meaning gets a new name and the old name is retired.

### `JobIDRule` {#connectorapi-jobidrule}

```go
const JobIDRule = "a driver that reports a job reports " + JobIDPath + ", derived where the machine " +
    "counts no jobs, and stable for the life of that print"
```

JobIDRule is the rule a host holds a driver to, stated once so that a driver author and the conformance suite read the same sentence.

A machine that counts its own jobs gives the driver a number to report, and a machine that names its jobs gives it a text to report as it is. A machine that does neither still has a print, and the driver derives an id for it: something stable for the life of that print and different for the next one, such as the file's name with the moment the print started. A derived id must survive the driver reconnecting to the machine mid-print, because a second id for one print is a second print in every record that reads it.

### `Admits` {#connectorapi-admits}

```go
type Admits interface {
    // Pending are the devices waiting for a decision, in a stable order.
    Pending() []DeviceRegistration

    // Approve lets one through, so its next poll carries the credential it
    // dials with. A code the table does not hold is ErrUnknownCode.
    //
    // by is who decided, as the host names them. It is recorded against the
    // registration: an operator asking after the fact which of us let this
    // printer onto the farm is asking a question only the decision can answer.
    Approve(ctx context.Context, code, by string) (DeviceRegistration, error)

    // Reject forgets one registration and every credential it held. A code the
    // table does not hold is ErrUnknownCode.
    Reject(ctx context.Context, code string) error
}
```

Admits is the half of a driver that holds a registration table an operator decides on. A dialect whose devices pair by displaying a code implements it, and the host publishes that table at /api/v1/registrations.

It is here, and its types are here, because that is what makes it reachable. An interface declared in the host with methods returning a type in the core's internal tree is one no module outside the core can ever satisfy: a third-party dialect whose devices pair by code would be shut out of the operator surface by the type system rather than by a decision. A driver that does not implement it admits a device without asking anybody and contributes no row to that surface, which is still a choice an author may make.

### `Arrivals` {#connectorapi-arrivals}

```go
type Arrivals interface {
    // Admit asks whether the host will take a device that has identified
    // itself, and returns the profile the host resolved for it. The driver may
    // narrow the profile and must not widen it. A refusal is ErrDeviceRefused,
    // and the driver must not serve that device.
    Admit(ctx context.Context, identity Identity) (profile Set, err error)

    // Arrived hands the host the session for a device Admit accepted. The host
    // owns it from that call and releases it when the session's state channel
    // closes. On any error the driver must close the session. ctx bounds the
    // handover, not the session, so a request context is fine.
    Arrived(ctx context.Context, session Session) error
}
```

```go

    // ForgetDevice withdraws every credential this driver issued for the
    // machine identity names, when it was issued before the moment given. The
    // moment keeps a registration the machine made after its record was
    // retired: that one is a new request, and a person may already have
    // approved it.

    // host may call it twice for one device. The withdrawal is durable when
```

ForgetsDevices is the half of a driver that can take back the credential it issued for one device.

A driver that issues no credential has nothing to take back and does not implement it. One configured to check no credential may keep what it holds, and take it back when it is called again under a setting that checks one.
