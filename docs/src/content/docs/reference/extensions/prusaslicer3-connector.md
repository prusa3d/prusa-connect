PrusaSlicer 3 Connector lets PrusaSlicer 3 use this server in place of Prusa Account and Prusa Connect. A person sets PrusaSlicer to offline mode and types the address of this server. PrusaSlicer then signs in through the [app pairing](../../scoped-credentials-and-app-pairing.md) of this server, lists the printers the person may use, and sends a print.

At install, an administrator approves the upload route with its largest file of 1024 MiB. The administrator may change that limit later on the extension's Uploads tab, up to 4096 MiB. Without the approval, PrusaSlicer cannot print to this server.

The administrator also approves one public route, `GET /account/api/v1/me/avatar.png`. It answers with no credential, because PrusaSlicer downloads the avatar without one. The picture is the person's initials on a coloured square, and its address alone decides it. Without the approval, PrusaSlicer shows no avatar.

A person signs in from PrusaSlicer with `view_resource` on the extension. To print, they need `operate_resource` on the extension, `operate` on the printer, and `read_storage` on the storages, because the printer takes the file from the extension's own folder. A role on the whole server gives all of them. A person with roles on single printers also needs the operator role on the extension and the viewer role on the storages. Without them, the print is refused after the slicer sent the file.

The README in `extensions/prusaslicer3-connector` lists every request PrusaSlicer makes and where each reply comes from.

The extension opens no port of its own. PrusaSlicer reads each printer's state from the printer list, which it reads again every 30 seconds.

## What it adds {#what-it-adds}

- **Print from PrusaSlicer**: a page of its own, with an entry in the sidebar
- **How to**: a tab on the module's page under Settings, Extensions
- **Set as current in PrusaSlicer**: a control under the header of each printer's page
- **Set as current in PrusaSlicer**: a small control on each printer in the listing

## What it needs {#what-it-needs}

- a server release `>=0.1.0-beta.2`
- the server methods `access.check`, `access.people`, `device.get`, `device.list`, `device.print`
- to ask whether a person may `operate`, approved at install
- a data directory of its own, which an update and a removal keep
- the list of the people on the server, with their names
- routes anybody may call without signing in: `GET /account/api/v1/me/avatar.png`
- routes whose request body the server writes into its data directory, with the largest body each asks for: `PUT /connect/app/teams/{team}/files/raw up to 1024 MiB`

It asks for no permission of its own. It acts only for the person who asks.

## Routes {#routes}

Every path is under `/api/v1/modules/com.github.aux.prusa3d.prusaslicer3-connector`. The extension's `openapi.json` describes each of them, and the server serves it at `openapi.json` under the same path.

| method and path | what it does |
|---|---|
| `GET /account/api/v1/me/` | The person behind the credential. |
| `GET /account/api/v1/me/avatar.png` | A picture of a person's initials. |
| `PUT /connect/app/teams/{team}/files/raw` | Send the file of a registered upload and print it. |
| `POST /connect/app/users/teams/{team}/uploads` | Register an upload to a printer. |
| `GET /connect/slicer/v2/printers` | The printers PrusaSlicer may print on. |
