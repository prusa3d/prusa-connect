Prusa printer logs keeps the log lines and the metrics that Prusa printers with Buddy firmware send, on this server and nowhere else. When a printer misbehaves, they say what it did. A person reads and filters them on the Prusa printer logs page or on a printer's Logs tab. An admin can add the newest of them to the diagnostics bundle of a support ticket.

To use it:

1. Install it and approve the two UDP ports it listens on. In a container, publish both ports as UDP, for example `13514:13514/udp` and `8514:8514/udp`.
2. Set each printer up. On the printer, open Settings, Network, Metrics & Log, switch on Enable Metrics and write this server's address as Host. The setup button on the page sends the same settings, and the printer asks a person to confirm them on its display.

A printer names itself by the MAC address of its Ethernet port. The extension matches that to a printer it knows, and a person can match an unknown MAC to a printer on the page.

UDP carries no proof of who sent a datagram, so anybody who can reach the two ports can send lines in a printer's name. Treat the lines as a hint about what a printer did, never as evidence, and keep the ports closed to networks you do not trust. A person sees the records of the printers they may see, and no others.

The README in `extensions/buddy-debug-logs` describes the formats, the limits on what one sender can do, and where the records are kept.

## What it adds {#what-it-adds}

- **Prusa printer logs**: a page of its own, with an entry in the sidebar
- **Logs**: a tab of its own on each printer's page

## What it needs {#what-it-needs}

- the server methods `device.command`, `device.list`
- the permissions `observe`, approved at install
- the UDP port 13514, `syslog`, approved at install, for printer log lines
- the UDP port 8514, `metrics`, approved at install, for printer metrics
- a data directory of its own, which an update and a removal keep

## Settings {#settings}

An operator writes them under `config:` in the extension's entry of the configuration.

| key | type | default | what it sets |
|---|---|---|---|
| `retention_hours` | int | `24` | How many hours a log line or a metric point is kept. |
| `max_mib` | int | `128` | The disk room both streams may take together, in MiB. The log lines keep a quarter of it. |

## Routes {#routes}

Every path is under `/api/v1/modules/com.github.aux.prusa3d.buddy-debug-logs`. The extension's `openapi.json` describes each of them, and the server serves it at `openapi.json` under the same path.

| method and path | what it does |
|---|---|
| `POST /data/purge` | Remove kept log lines and metrics. |
| `POST /devices/{device_id}/setup` | Ask a printer to send its log lines and metrics. |
| `GET /export` | One page of a download as text. |
| `GET /logs` | One page of log lines, newest first. |
| `GET /metrics/names` | The metrics a printer sent. |
| `GET /metrics/series` | One metric as points for a chart. |
| `GET /sources` | Every MAC address that sent something. |
| `PUT /sources/{mac}` | Match a MAC address to a printer by hand. |
| `GET /status` | The ports, what arrived and the room taken. |
