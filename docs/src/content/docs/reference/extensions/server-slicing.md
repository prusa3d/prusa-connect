Server slicing turns a 3MF project into G-code on this server, with the command line of the public PrusaSlicer. A person picks a project in a storage, or sends one with the request, and says where the G-code goes. A worker runs PrusaSlicer in a process of its own and writes the G-code into the storage, where a printer prints it like any other file. The Slicing page lists the PrusaSlicer versions and the jobs.

Before the first job, an administrator installs a PrusaSlicer version on the Slicing page. The extension offers the releases GitHub publishes, checks each download against its SHA-256 and keeps several versions side by side. A release that publishes no SHA-256 installs only when the administrator confirms it.

The Linux builds on GitHub that the extension can install end at PrusaSlicer 2.8.1, and at 2.7.4 on arm64. For a newer version on Linux, and in the container image, which carries no PrusaSlicer, name a manifest of builds you host in `manifest_url`. Or install PrusaSlicer on the machine and name its executable in `local_binaries`.

A slicer run takes a lot of memory. On a small machine such as a Raspberry Pi with 4 GB, keep `max_jobs` at 1. Each run is bounded by the module's memory budget, shared by `max_jobs`, and the extension has no memory setting of its own. Change the budget with `memory_mib` on the module's resource, as [Extensions](../../config/extensions.md#how-much-memory-a-module-may-use) says. An install or an update drops the `memory_mib` setting of an earlier version by itself. A server-slicing module declared in `config.yaml` keeps the key and fails to start with `RESOURCE_PLUGIN_SETTINGS` until you delete it there.

A job reads the project as the person who asked for it. The G-code is written after the run, by the extension, once the server confirmed that person may still write into the storage. Installing and removing a version takes `configure_resource` on modules, which an administrator holds. Each output name starts with eight characters of a hash of its target, so two outputs never share one short name on a printer's FAT storage.

The README in `extensions/server-slicing` describes the manifest format, the jobs and the error codes.

It connects outside Prusa Connect to:

- api.github.com port 443 from the process: Lists the PrusaSlicer releases every six hours, while github_releases is on. Sends: The request, and the github_token setting when one is set.
- github.com port 443 from the process: Downloads the PrusaSlicer build an operator installs from the GitHub releases. Sends: Only the request for the file.
- *.githubusercontent.com port 443 from the process: GitHub serves the release files from there after a redirect. Sends: Only the request for the file.
- the host in the setting manifest_url port 443 from the process: Reads the operator's manifest of builds, when it is an https address. Sends: Only the request for the manifest.

## What it adds {#what-it-adds}

- **Slicing**: a page of its own, with an entry in the sidebar
- **Slice**: an item in the action menu of each file in storage, for `.3mf`

## What it needs {#what-it-needs}

- a server release `>=0.0.1-alpha.7`
- the server methods `access.check`, `storage.read`, `storage.stat`, `storage.write`
- the permissions `read_storage`, `write_storage`, `configure_resource`, approved at install
- a data directory of its own, which an update and a removal keep

## Settings {#settings}

An operator writes them under `config:` in the extension's entry of the configuration.

| key | type | default | what it sets |
|---|---|---|---|
| `max_jobs` | int | `1` | How many projects slice at the same time. |
| `max_queued` | int | `16` | How many jobs may wait. One more is refused until a job finishes. |
| `timeout_minutes` | int | `30` | How long one slicer run may take before it is stopped. |
| `threads` | int | `0` | The threads one slicer run may use. 0 lets the slicer choose. |
| `max_project_mib` | int | `512` | The largest project a job takes, in MiB. |
| `keep_jobs` | int | `200` | How many finished jobs the module remembers. |
| `github_releases` | bool | `true` | Offer the PrusaSlicer releases that GitHub publishes, read from its API every six hours. |
| `github_token` | secret | none | A GitHub token for reading the releases, which raises the limit of 60 requests an hour. |
| `manifest_url` | string | none | An https address or an absolute path of a manifest of builds you host. Empty offers none. |
| `local_binaries` | list | `[]` | Absolute paths of PrusaSlicer executables already on this machine. |

## Routes {#routes}

Every path is under `/api/v1/modules/com.github.aux.prusa3d.server-slicing`. The extension's `openapi.json` describes each of them, and the server serves it at `openapi.json` under the same path.

| method and path | what it does |
|---|---|
| `GET /jobs` | The caller's jobs. |
| `POST /jobs` | Slice a project in a storage. |
| `POST /jobs/upload` | Slice a project sent as the body. |
| `GET /jobs/{id}` | One job. |
| `POST /jobs/{id}/cancel` | Stop one job. |
| `GET /slicers` | The installed and the offered slicers. |
| `PUT /slicers/default` | Choose the version a job gets. |
| `POST /slicers/install` | Install one offered version. |
