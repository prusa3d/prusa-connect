The server can encrypt two connections, each on its own:

- **The web app and the API.** With a certificate and its key in
  `core.api.tls`, the server speaks HTTPS, with TLS 1.3 and newer.
- **The printers.** A printer speaks TLS 1.2 with one ECDSA cipher suite, which
  is older than what the web app speaks. So encrypted printers connect on a
  listener of their own, on another port, written under the connector in
  `core.connectors.<name>.config.listener`. See [Printers](printers.md).

Once the web app is encrypted, printers cannot use its port at all, so they
need that listener, encrypted or not.

The setup wizard has a step for both. It can make the certificates for you: a
root certificate of the server's own, and two it signs, one for the web app and
one for the printers. They are written to `config/config.d/certs`. A
printer trusts that root certificate only from the file `connect.der` on its
USB stick, and only when its settings file says `custom_cert = 1`.
`core.frontend.printer_custom_ca` makes the page that adds a printer write that
line, and offer `connect.der` for download beside the settings file. It matters
only when the printers connect over HTTPS.

To make the certificates yourself, read [Certificates](../certificates.md).
Both listeners read a replaced certificate and key without a restart, see
[Replace a certificate without a restart](../certificates.md#replace-a-certificate-without-a-restart).

### core

Every key has a working default, so a file with no `core:` block starts a server. A key this build does not read is refused at startup, with the line it is written on.

| key | type | default | required | what it does |
|---|---|---|---|---|
| <a id="key-core-api-tls-certificate"></a>`core.api.tls.certificate` | text | - | no | PEM file with the certificate of this server, followed by the certificates of the authorities that signed it. When both TLS keys are empty, the server uses plain HTTP. |
| <a id="key-core-api-tls-key"></a>`core.api.tls.key` | text | - | no | PEM file with the private key for that certificate. |
| <a id="key-core-frontend-printer-custom-ca"></a>`core.frontend.printer_custom_ca` | true or false | `false` | no | The printers' certificate is signed by an authority of your own, so the add-printer page asks the printer to trust the connect.der on its USB stick. |
