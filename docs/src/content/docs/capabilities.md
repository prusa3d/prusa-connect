Generated by 'make generate-capabilities' from the profiles this build ships, the closed sets in sdk/connectorapi and the host feature table this build declares. Do not edit.

A driver declares what its code can do in `Baseline()`, as capability keys. This page is the vocabulary those keys are drawn from: what the printers this product already drives declare, and what each argument accepts. The path from nothing to a driver that declares them is [writing a printer driver](./writing-a-driver.md), and what the host promises in return is [the connector contract](./connector-contract.md).

The key set is not closed by a gate. `sdk/connectorapi` checks a key's syntax and nothing checks that a key means something, so a driver may declare a key that is not here and it will resolve, validate and reach `Do` like any other. What it will not do is reach a caller that knows what to send: the API, the frontend and every profile in this tree speak the keys below. A dialect that needs a verb nothing here names is a change to this vocabulary, not a private extension of it.

This page lists the keys the shipped profiles declare. Another driver may name an argument differently, such as `celsius` for a nozzle target, and narrows each range per machine. What one device accepts is `GET /api/v1/devices/{device_id}/capabilities`: every verb it resolved to, and for each argument its name, type, range, default, closed set of values and unit. The unit is one of `celsius`, `percent`, `mm`, `mm/min`, `s` and `byte`, and the driver declares it.

A key whose meaning changes gets a new name and the old one is retired in a list the profile package holds, which is refused for good. No schema language detects a field that kept its name and changed what it means, so the retirement list is the mechanism.

## Contract version

This build serves connector contract `1.0.0`. A driver declares the version it compiled against in its descriptor's `Contract` field, and a host serving another major refuses it at registration rather than at first use.

## Value kinds

Arguments travel as text. The kind is what tells the host how to read one before a driver sees it.

- `flag` no value. It belongs to a key that answers only "can you", such as a verb or a firmware feature
- `string` free text, bounded by the limit when one is declared
- `integer` a whole number
- `number` a fractional number
- `boolean` `true` or `false`, in those spellings and no other
- `opaque` a value the host passes through untouched, such as an embedded JSON document

## Commands

A verb accepts exactly the arguments for which the descriptor carries an argument key. There is no wildcard: an argument nothing declares is refused by the host before a driver is reached, so a verb is subtracted by leaving its key out and an argument the same way.

`limit` is an inclusive bound on the value's magnitude: the absolute value of a number, the length in bytes of a string. `min` is an inclusive lower bound on a number itself, which is what says that a target may not go negative. The values below are the loosest form any shipped profile gives the key, and one printer's own descriptor may be narrower.

## Host features

A host feature is a key the server declares about itself. A module names one under `requires` in its manifest, and a host that carries no such key refuses the module at install rather than starting it against something that is not there.

| feature | carried by | what it promises |
| --- | --- | --- |
| `core.feature.ui` | the full build | The host serves a browser application a module can extend: six slots it can fill, across the app, a printer's page, the printer listing and the settings screen |
