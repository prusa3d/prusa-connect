Generated by 'make generate-error-codes' from the fault registry. Do not edit: change the registration in Go and regenerate.

Every failure a client can see carries `code`, a stable `domain/REASON` identifier, next to an English `title`. Branch on `code`. Fall back to `title` for a code the client does not know, and quote `trace_id` when reporting one.

A refusal answers with the values it interpolates, under `params`. The **parameters** line on each code below names the keys that member carries, and it is a promise a client may read. Read them rather than parsing the `detail` sentence, which is English prose and is not a contract. A refusal about something the caller named puts what it named there: a 403 says which action was missing and on which object.

A redacted code renders `code`, `title`, `status` and `trace_id` and nothing else. Its occurrence detail and its params stay in the server log line that the trace id keys.

A retryable code is worth repeating with backoff. Every other code fails the same way however often it is sent.

Each code below is its own section, anchored by the code itself: `core.printer/GCODE_NOT_ALLOWED` is at `#core-printer-gcode-not-allowed`, so a link to one code can be written from a response without opening this page.

Every refusal carries that address already, under `type`. It is this page and the code's own section of it, so a screen that has just failed can offer it as a help link and the person lands on what went wrong and what to do about it.

The machine-readable copy of this page is `docs/errors/error-codes.json`.

## Parameter keys

Every key a `params` object can carry is in this set, and a code that declares a key outside it fails the build. A key names one fact: the instance a refusal is about is `resource`, carrying the kind, a colon and the name. A key holding a bound names its unit or its subject, so a byte count is `limit_bytes` and a count of streams is `limit_streams`.

### `core.auth/ACCESS_DENIED` {#core-auth-access-denied}

The caller may not perform that action on that object.

- **status** `403`
- **retryable** no
- **occurrence detail** shown
- **parameters** `object`, `action`, `verb`, `command_id`
- **what to do** Ask an administrator for a grant on the device or on a group that contains it.

## core.printer

### `core.printer/CAPABILITY_NOT_SUPPORTED` {#core-printer-capability-not-supported}

The printer does not have that capability.

- **status** `409`
- **retryable** no
- **occurrence detail** shown
- **parameters** `verb`, `verbs`, `verb_count`, `command_id`
- **what to do** Send one of the verbs this error carries as verbs, which is the capability set this server resolved for the printer. It is a JSON array of strings and not a joined list, so a key reads back whole. verb_count is how many verbs the printer has: a count above the length of the array means the array is the first 128 and the printer's own capability set is the rest. The set is handed out with an epoch, and the epoch moves whenever the printer reconnects, so a set kept from an earlier epoch describes a printer that is no longer there: read it again rather than caching it across a reconnect.

### `core.printer/COMMAND_FAILED` {#core-printer-command-failed}

- **status** `409`
- **retryable** no
- **occurrence detail** shown
- **parameters** `verb`, `machine_reason`, `command_id`
- **what to do** Read the machine reason this carries, which is the printer's own word for what went wrong, then read the printer's state. The printer accepted the command and failed part way through it, so it may have changed something: this is not resent for you and sending it again is a second attempt rather than a first.

### `core.printer/COMMAND_FAILED_WITHOUT_REASON` {#core-printer-command-failed-without-reason}

### `core.printer/COMMAND_QUEUE_FULL` {#core-printer-command-queue-full}

### `core.printer/COMMAND_REFUSED` {#core-printer-command-refused}

## core.validation

### `core.validation/ARGUMENT_MALFORMED` {#core-validation-argument-malformed}

The value is not in the form the argument accepts.

- **status** `400`
- **retryable** no
- **occurrence detail** shown
- **parameters** `verb`, `argument`, `kind`, `allowed_characters`, `limit_characters`, `command_id`
- **what to do** For a number, send a whole or a fractional number. For a boolean, send true or false. For text, send only the characters allowed_characters names, and no more than limit_characters of them.

### `core.validation/ARGUMENT_MISSING` {#core-validation-argument-missing}

The command needs an argument that was not supplied.

- **status** `400`
- **retryable** no
- **occurrence detail** shown
- **parameters** `verb`, `argument`, `command_id`
- **what to do** Supply the argument. It has no default, so there is nothing for the server to fall back to.

### `core.validation/ARGUMENT_NOT_SUPPORTED` {#core-validation-argument-not-supported}

The printer does not support that value for the argument.

- **status** `400`
- **retryable** no
- **occurrence detail** shown
- **parameters** `verb`, `argument`, `supported`, `command_id`
- **what to do** Choose one of the supported values, which this error carries as a JSON array of strings. It is an array and not a joined list so that a value containing a comma reads back whole.

### `core.validation/ARGUMENT_OUT_OF_RANGE` {#core-validation-argument-out-of-range}

The argument is outside the range the printer accepts.

- **status** `400`
- **retryable** no
- **occurrence detail** shown
- **parameters** `verb`, `argument`, `max`, `min`, `command_id`
- **what to do** Send a value no further from zero than max, and at or above min. The refusal carries whichever of the two the value broke.

### `core.validation/ARGUMENT_UNKNOWN` {#core-validation-argument-unknown}

The command does not accept that argument.

- **status** `400`
- **retryable** no
- **occurrence detail** shown
- **parameters** `verb`, `argument`, `command_id`
- **what to do** Send only the arguments the capability declares. An argument that used to exist is not silently ignored, because a command carried out with a dropped argument is not the command that was asked for.

### `core.validation/BODY_TOO_LARGE` {#core-validation-body-too-large}

- **status** `413`

- **occurrence detail** shown

- **occurrence detail** shown
- **parameters** `limit_streams`
- **what to do** Close a stream before opening another. One stream carries every origin the caller may observe, so a second is rarely needed; narrow one with the origins parameter instead.

### `core.validation/UPLOAD_TOO_LARGE` {#core-validation-upload-too-large}

The file is larger than this server accepts.

- **status** `413`
- **retryable** no
- **occurrence detail** shown
- **parameters** `limit_bytes`
- **what to do** Send a file of at most {limit_bytes}. An administrator sets the largest file with core.api.max_upload_size.

### `core.validation/VERSION_CONFLICT` {#core-validation-version-conflict}

The instance changed since the version the write quotes.

- **status** `412`
- **retryable** no
- **occurrence detail** shown
- **parameters** `resource`, `version`
- **what to do** Read the instance again, reapply the change to what it now says, and send the new ETag. Somebody else wrote it, possibly by editing the configuration file directly.
